# GeoRAG — Member 2 Package Index

Model upgrade, scientific validation & handoff package.
Built 2026-10-22 from the team Drive (`GeoRAG`, never modified).
Every packaged file is listed with size + SHA-256 in `MANIFEST.csv`.

**Read in this order:** `README.md` → `docs/EXPERIMENT_DESIGN.md` (protocol) →
`results/model_comparison.md` (numbers) → `docs/LIMITATIONS.md` →
`docs/HANDOFF_MEMBER3.md` (how to consume the outputs).

---

## Top-level files

| File | What it is |
|---|---|
| `README.md` | Main narrative: what was done, headline results, class schemes, reproduce steps |
| `INDEX.md` | This file |
| `MANIFEST.csv` | path, size_bytes, sha256 for every packaged file (integrity check) |
| `requirements.txt` | Python deps used (pinned by experience, see LIMITATIONS §6 for the oneDNN note) |
| `run_all_transformers.sh` | Runs the full 12-run transformer matrix |

## `docs/` — documentation

| File | What it is |
|---|---|
| `docs/EXPERIMENT_DESIGN.md` | The 6-experiment protocol, written **before** any training, plus logged deviations |
| `docs/DRIVE_INVENTORY.md` | Verified recursive inventory of the team Drive; documents what was and was not there |
| `docs/MODEL_INVESTIGATION.md` | Sources-backed investigation of "MTS" and "Dual-Level Attention Lightweight ViT"; why adaptations were needed |
| `docs/LIMITATIONS.md` | Honest list of data, method and environment limitations |
| `docs/HANDOFF_MEMBER3.md` | Technical handoff for the GIS/RAG decision-support stage |

## `src/` — pipeline code (runs top to bottom)

| File | What it does |
|---|---|
| `src/common.py` | Shared: paths, seeding, splits, standardisation, one `evaluate()` for all models |
| `src/01_build_features.py` | Builds the 9-feature stacks + labels + validity masks into `derived/` (verified against Member 1's own index rasters) |
| `src/02_run_baselines.py` | Retrained RandomForest + XGBoost baselines, 6 experiments |
| `src/models.py` | The two adapted transformer architectures (`mts-lite-adapted`, `dla-lite-adapted`) |
| `src/03_train_transformer.py` | Transformer training/eval, same splits as baselines; `--spatial` for the blocked variant |
| `src/04_collect_results.py` | Collects every run into `results/model_comparison.*`, `per_class_metrics.csv`, `recommendation.json` |
| `src/05_predict_rasters.py` | Full-grid prediction rasters per model per year (GeoTIFF, output class scheme, metadata tags) |
| `src/06_change_analysis.py` | Change detection, transition matrices, area statistics (geodesic pixel areas) |
| `src/07_figures.py` | Comparison bars, confusion matrices, per-class F1, maps, change maps, heatmaps |
| `src/08_spatial_validation.py` | The separate spatially independent (blocked) validation on 2015 |

## `experiments/` — raw run outputs

- `experiments/baselines/` — per-run JSON metrics (RF + XGB × 6 experiments)
- `experiments/transformers/` — per-run JSON metrics + `checkpoints/` (.pt files for every transformer run, including the blocked spatial variant)

## `results/` — aggregated tables

- `model_comparison.csv` / `.md` — the main results table (all models × 6 experiments)
- `per_class_metrics.csv` — per-class precision/recall/F1 per run
- `recommendation.json` — machine-readable aggregation + chosen model
- `spatial_validation.json` / `.csv` — the blocked-holdout experiment (kept **separate** from the main table)
- `environment.json` — hardware/software environment of the runs

## `outputs/` — generated geospatial products

- `outputs/predictions/` — `pred_{2015,2020,2025}_{model}.tif` per model family + `prediction_manifest.json`
- `outputs/change_detection/` — per-model transition matrices, built-up change analysis (JSON + CSV)
- `outputs/areas/` — per-model per-year class area statistics (CSV, geodesic m²/km²)
- `outputs/figures/` — all generated figures (PNG)

## Inputs (preserved, unchanged)

- `drive_data/`, `drive_downloads/` — copies of the Drive inputs (labels, indices, satellite scenes, Member 1 zips, OSM pbf, PDF)
- `derived/` — regenerable feature stacks (`01_build_features.py`); only `manifest.json` is packaged, the `.npy` arrays are rebuilt by step 1 of the README recipe

## Excluded on purpose

`.venv/`, `logs/`, `extracted/` (regenerable by unzipping the two Drive zips — see README §5),
`derived/*.npy` (regenerable), `__pycache__`, the ZIP itself.

## Integrity

```bash
# from the unzipped package root:
sha256sum -c <(awk -F, 'NR>1{print $3"  "$1}' MANIFEST.csv)
# and MANIFEST.csv itself is regenerated by tools/build_package.py on rebuild
```
